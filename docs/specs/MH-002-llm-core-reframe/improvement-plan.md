## 1. 先固定用户买到的结果

产品只替代单个招标文件包的五项分析：摘要、要求清单、评分/价格规则、
风险与补遗分析、有依据的文档问答。不搜索、不代写投标书、不猜中标概率。

成功应体现为用户能回答：采购什么？必须交什么？怎么评分？哪版条款有效？
有什么风险/矛盾？还有什么必须澄清？每项重要答案能够回到源文件物理页。

## 3. 目标架构：简单、固定、可观察

```text
上传/校验 → PDF.js 逐页证据 + Monid 解析
          → LLM 逐文档完整抽取
          → LLM 跨文档合并、补遗处理与关键结论复核
          → 代码核验证据位置、结构和精确计算
          → 摘要 / 要求 / 评分 / 风险 / 版本变化
          → LLM 依据文件证据回答追问
```

这不是无限自主 agent 循环。三个固定职责：抽取、合并复核、问答。
可以按页数/上下文容量分批，但不按关键词选择“唯一值得读”的片段。
每个源页都有处理记录；失败、截断或遗漏显示为覆盖缺口，不冒充完整。

### 模型与代码的职责边界

- LLM：相关性、要求类别、主体与条件、数字/日期的含义、补遗目标、
  冲突、风险、结论是否得到证据支持，以及回答内容。
- 代码：权限、大小/哈希、页编号、引文精确定位、JSON 结构、对象引用完整性、
  按明确操作更新状态、按明确公式精确计算、预算、幂等、删除和审计。
- 不能让代码从自然语言重新猜含义。LLM 输出的结构化数值可做类型/范围检查，
  但数值属于什么条款、代表上限还是下限，必须由 LLM 结合证据判断。
- 原文引用匹配只证明出处，不代表已经证明解释正确。关键事实需要模型在
  合并复核时重新查看原文和相关补遗，而不是只复述第一阶段摘要。
- 文档作为不可信数据；运行时不给文档任何浏览/执行能力。LLM 判断问题范围，
  不用提示注入关键词词典来决定文档含义，也不靠模型保证工具隔离。

### 最小数据模型，不建立通用 ontology 平台

1. `EvidenceSpan`：服务器持有的文档身份、物理页、原文片段与稳定证据 ID。
2. `Finding`：类型、主体、值、必要限定条件、证据引用，以及模型给出的
   `supported / needs_review / unknown / conflicted` 状态；出处验证另设字段。
3. `AmendmentOperation`：变更来源、目标 Finding/整节或表格范围、
   `add / replace / delete`、新值、原文依据。语义目标由 LLM 给出。
4. `Answer`：回答、证据、适用版本、可回答状态。网页和 API 从同一模型投影。

复用已有文档 manifest 与处理/费用回执保存文件身份和覆盖/执行记录；
它们是运行证据，不是另一套有权覆盖 Finding 的语义判决系统。

服务端验证 ID 存在、文档属于本次运行、引文属于源页、操作图无非法引用。
替换后旧事实仍保留为 superseded。无法确定目标时保留候选并请求澄清，
不得靠上传顺序或词典自行选一个。文档内部冲突不能被“最后出现的值”覆盖。

不确定性局部化：提交方式不明只影响提交方式及其依赖结论，不隐藏无关评分、
风险或问答。文件无法读取/文档混入等问题须展示影响范围；完整性声明只能
来自实际覆盖与审核，不把“模型返回合法 JSON”当作完整分析。

## 4. 问答需要独立解决证据生命周期

现状会删除页索引，结果摘要不是全文。仅给摘要换上 LLM 仍不等于 Document Q&A。

建议方案（实施前确认隐私选择）：用户明确开启文档问答后，私有、加密、按
run/owner 隔离地保留规范化全文和逐页证据，最长 24 小时，与分析结果同步
到期；原 PDF 仍尽早删除。保留内容不进 Git/日志。用户提前删除、到期、任务
失败和问答过程中撤销都要覆盖。UI 和隐私说明必须先反映新增保留对象。

未同意时维持原来的清理承诺，清理后明确告知全文问答不可用，不能退回关键词
问答冒充相同功能。原有运行也不能凭摘要宣称支持全文问答。第三方保留期照实披露。

问答优先把完整文件包及当前版本关系交给 LLM；超出上下文时，对所有页进行
LLM 相关性检查，再综合有证据的结果，不能只用关键词 top-k。语义检查不得
静默漏页；无法覆盖时返回 limited/needs_review，而不是确定性“不存在”。

每个问题需要独立的 owner 检查、幂等键、配额和成本记账，使用现有安全/预算
基础设施。必须先记账再付费；失败不无限重试。现有 `answer()` 禁用方法不能
直接打开后绕过这些约束。新接口与前端共同约定证据过期/未同意/模型失败状态。

## 6. P0 最小实验：先证明新方法值得迁移

固定一个模型版本、三份短 prompt 和 schema 版本。使用已缓存的公开原文，
选取以下已知失败边界及必要相邻上下文，不再付费重新解析完整文件：

- Edmonton p14、p43、p15–17：最低评估价、最多三人、安全要求与附件矛盾。
- CER Amendment 002 的完整截止时间条款；003 p2/p5/p6 的内部矛盾；
  001 的付款整体替换，以及 003 与原文件对应的完整表格范围。
- 至少一份未用于修提示的人工标注独立材料，以及等义改写、陌生提交渠道、
  否定/条件、无关保险/价格歧义的对照组。固定盲测答案，不把答案写进 prompt。
- 一组至少 12 个问题：跨页、补遗版本、未进入摘要的事实、明确未知；
  其中包含中文追问英文文件，防止英文词重合被误认为理解。

输出留在独立、忽略入库的开发缓存，以 source SHA + parser/model/prompt/schema
版本区分；保留真实请求/响应的安全本地回放副本和各阶段结果，不覆盖旧缓存。

通过条件：关键黄金项正确、引用均可定位、评分公式重算零误差、无不支持的
确定结论、无与提交无关的全局清空；盲测材料表现单独报告。整表替换必须核对
完整旧/新条目清单，不是只找到“replace”一句。问答12题按人工标准核对全部。

反证条件：仍要加入模板词典/文件特例才能过；完整表格持续漏项；引用正确但
结论持续错误；成本/延迟不能满足可接受交付。任一出现就停止大规模迁移，
记录失败并调整分块、上下文或模型，不把旧规则加回来。

本任务不执行实验。恢复实施后先预估请求成本并给实验设明确运行次数；
开发每日上限豁免不等于无限重跑。建议每版一次捕获，最多两轮针对性提示修订；
失败后重新分析原因。固定旧响应的重放只能验证代码，不能验证新 prompt。

## 7. 验证节奏、兼容与回滚

- 改代码：只测 CodeGraph 影响分析对应的模块与固定回放，不重复 Monid。
- 改 prompt/schema：必须有新的、显式计费的模型实验；只运行受影响样例。
- 单文档/补遗里程碑：各跑一次相关黄金集与盲测；完整性与准确性分别报告。
- 发布候选：一次全量 lint/typecheck/tests/build/UI；旧测试保留原始输入和期望
  业务事实，移除对特定正则、词典或全局 veto 实现细节的依赖，不删除失败证据。
- 最终：独立 Reviewer 检查高风险引用至少 12 处及整份报告；零 P0/P1 后再
  做真实集成。不把一次运行标成 P95，也不把缓存重放标成模型稳定性10/10。

在 `codex/` 分支分阶段提交，保留基线可回退。新旧 schema 明确版本化，旧
运行只读兼容，不回填或伪造新结论。先本地/影子比较，不启用隐蔽的旧语义
fallback。严重失败回滚整个候选版本或禁用分析入口，而不是混用两套判决。

延迟、模型选择和最终成本是实验结果，不在此承诺未经测量的完成时间。
主要工程产出应是更少的语义规则、更完整的报告，而不是更多审计层或测试次数。
